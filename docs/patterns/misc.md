# Matching patterns: misc

Everything else. One pattern per line, so `grep -i <keyword> docs/patterns/*.md` returns whole entries.

- **Shared scratchpad dir:** parallel agents share one scratchpad directory; use a private subdirectory for variant files or `a.c` gets clobbered.
- **`fnvariants` scores are diff-line counts: lower is better** (0/OK = match). Sort ascending.
- **Dead stack copy of a rodata triple (fn_3_FD51C):** `V3U v = *(V3U*)rodata; *(V3U*)(p+0xC) = v;` reproduces lwz once + both stores + the stack store. A `u32 t[3]` dead copy is optimized away.
- **`(u32)rand() % 23`** gives `mulhwu`, `rand() % 23` gives signed `mulhw`.
- **Sum of scaled terms (`n*0x18 + n*4 + n*4 + n*2`) reassociates unpredictably:** permute the terms AND mix `* k` with `<< k`; `(n << 2) + (n << 1) + (n << 2) + n * 0x18` reproduced the original schedule in fn_3_FA3C0.
- **Clone families (menus rep_0788, rep_0B08):** many functions are byte-identical bodies (e.g. 14 state-machine functions of 436 B, `fn_2_6C020` == `fn_2_6F78C`). Group unmatched functions by an md5 of label-normalised asm; one match gives the whole family. Jump-table clones can differ only in the table, so compare `jumptable_*` contents too (`fndiff` never says MATCH for them; trust report.json).
- **`opt_propagation off` plus `s32 one = 1;`** keeps a hoisted `li rN,1` for several stores and a `slwi` index (menus fn_2_52CC).
- **Symbol splits fix pooled-base reloc differences:** when a `sym+0xC` reloc is folded by CW but the original has a separate symbol, split it in symbols.txt (menus fn_2_B508, fn_2_6784).
- **Never let `fnvariants` hit the shell timeout:** an interrupted run leaves a variant in the source; run it in the background.
- **Stale-r3 result:** `sndFXCtrl(vid, 0x5B, x)` after `sndFXStartEx(...)` passes the first call result.
- **`targsupp` TRK stubs show 0% (one `ASM` function with `entry` labels; separate C `ASM` functions get padded by `-func_align 16` or dead-stripped):** write it as `targsupp.s` with `.balign 16` and four `.fn` blocks; mwld keeps them and the shasum passes.
- **`x = tbl[off + base[idx2]++]` as one statement** gives the original schedule; separate `n = base[..]; base[..] = n + 1` does not (fn_3_10768C).
- **s8 table value passed to an s8 parameter: original has `lbzx; extsb` with the argument `li` scheduled before the load (fn_3_AEC50):** declare the table `u8[]` and pass `(s8)tbl[i]`; an `s8[]` table gives no extsb, and `(s32)` on an s8 table schedules `li r3` late.
- **`cmplwi` on a reused `flags & 4` test, and a re-extended `count` compare (fn_2_46D94):** the flags param is `u32` (an `s16` adds `extsh`, `s32` gives `cmpwi`); `lha; extsh rC,count; addi; extsh; sth; cmpw` is `if (++*sel >= count)`, not `*sel = v = (s16)(*sel + 1); if (v >= count)`.
- **`lbl_2_bss_X + 0xA/0xC/0x10` offsets off an unrelated bss symbol (fn_2_4917C):** these are file-static variables addressed from the unit's .bss base, which the original keeps in a saved register (`addi r31, base@l`). An `extern` struct (here `lbl_2_bss_55C0`) is correct C but reloads the address (78%).
- **`i % 3` recomputed after an earlier `i % 3` test (fn_3_12F424):** write the second one as `i - (i / 3) * 3`; CW CSEs two `%` but not `%` with the expanded form.
- **Linking a REL unit (challenge rep_7BA0/7978/7A28):** REL files are built with `-inline deferred`, which emits a file's functions in reverse source order, so a unit only links once its functions are listed from highest to lowest `.text` address (`python3 tools/reverse_fn_order.py src/<unit>.c`; per-function matching does not care). Same-file inlining still follows the reversed order (rep_7978's fn_1_273D8 inlines into fn_1_26D28 only when defined before it). Its `.rodata` must come from `header_rep_inline.h` (see floats.md) and the `.data`/`.bss` it owns must be defined in the file; then flip the object to `Matching` and check `dtk shasum`.
- **`add rT,base,idx; lbz 0(rT)` where the original has `lbzx` on a global table (HVQM4, MWCC 1.2.5: fn_800E156C, fn_800E11C8):** 1.2.5 never uses `lbzx` with a `lis/addi` constant base under normal optimisation; `#pragma opt_propagation off` (reset after the function) reproduces `lbzx` and the `addi rX,rY,0x0` register copies. It can hurt other loops (counted loops lose their constant start), so try it per function.
- **Whole SDK-style unit 1-2 instructions off on scheduling (charPipeline DSList, file_80091450):** try the unit under `mw_version="GC/1.2.5"` before fighting the C; the whole unit matched. Same quick test (all `#if NONMATCHING` -> `#if 1`, ninja, objdiff report) rules a version in or out in a minute.
- **`stb rN` of the same register to an `s8` and a `u8` field (fn_8001A3FC):** chain the stores, `u8field = s8field = -1;`; two separate `= -1`/`= 0xFF` statements materialise `li -1` and `li 0xff`.
- **Expression association decides scheduling (fn_800247E4):** a short pure expression that only differs in instruction order matched after a random search over association/locals: `s32 row = ((y / 4) * 4) * width; return bpt * ((x % 4) + (((y % 4) << 2) + (row + ((x / 4) << 4))));`.
- **Linking a REL unit (game rep_2940 and 45 others):** `-inline deferred` emits functions last-defined-first, so a unit only links once its functions are written in **reverse address order** (fndiff/objdiff don't care, the linked .rel does). Own `lbl_3_rodata_*` float externs must become literals (and `x += -0.5f` rather than `x = x + (-0.5f)` keeps the operand order); when MWCC then addresses them through a pooled `...rodata.0` base the unit needs `extra_cflags=["-pool off"]` (rep_1CB8, rep_2308, rep_940, rep_1D58) or `#pragma pool_data off` around those functions. The weak `dolsqrtf2` constants must precede `repHeaderData` in the first unit (include `UnknownHomes_Game.h` before `header_rep_data.h` in rep_0).
- **Wrong global that fndiff misses (fn_3_B95EC):** REL fndiff shows every `lbl_3_bss_*` as DATA, so `lbl_3_bss_1901 = 0` vs the original `lbl_3_bss_1902` printed MATCH; linking the unit (reloc tables differ) caught it. Compare relocation targets when promoting.
- **Scoring tip:** fnvariants/fndiff silently score a stale `.o` when the variant fails to compile; when a change gives exactly the old score, build the object with `ninja build/GYQE01/src/<unit>.o` to see the error. (CW rejects initializers for `AssetLoadInstructions`' bitfield union; use a `u32 [n][4]` table as `lbl_3_data_10ACC` does.)
- **Unit's data section at 99.x% in objdiff although every object matches (menus rep_0730, auto_00_0008782C):** the split includes the alignment padding before the next unit (dtk names it `gap_..`); end the split at the last object (`end:0x784` instead of `0x788`) and dtk makes the gap its own auto unit. Only `matched_data` of sections at 100% counts.
- **Extra 16 bytes of `.rodata` (`_half`/`_three` doubles) in a REL unit that includes UnknownHomes_Game.h (menus rep_0FD8, rep_0730):** that header makes `dolsqrtf2` `extern inline`, emitting its statics in every object (the linker drops the copies). Include `"math.h"` then `#undef SQRT2_LINKAGE` before UnknownHomes_Game.h. The original keeps one copy, in menus' first unit (rodata 0x0..0x10).
- **Common .bss / `-common on` (menus):** see docs/common_bss.md. File-local `.bss` must be `static`; an unreferenced `static` array is still emitted, so padding objects can be defined (`lbl_2_bss_B2C8`).
