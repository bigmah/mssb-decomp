# Matching patterns: floats

Float/double constants, f-register order, int<->float conversion, sqrt, fabs, compares. One pattern per line, so `grep -i <keyword> docs/patterns/*.md` returns whole entries.

- **Hoisted/aliased loads and register picks (fn_2_84388, fn_2_805DC, fn_2_73994, fn_2_760CC):** `((s32*)((u8*)&sym + 0x10))[i]` (not `*(s32*)((u8*)&sym + i*4 + 0x10)`) gives `add; lwz 0x10(rN)`; `(tbl + k*6)[idx]` not `tbl[k*6+idx]`. A value read in a later statement but loaded early (`lwz r5,0x44(r5)` after two stores) needs `cur = sym[..]` placed after the 2nd store in source (script all positions). For `(f1 != 0) + (f2 != 0) == 2` where the first result must reuse the dead `o` register, `u8 n = f1 != 0; if (n + (f2 != 0) == 2)` matched; `s32 n` took a fresh saved reg and a single `A + B` expression evaluates right operand first. A call whose argument regs are never set before the `bl` still takes the live `r3`/`r4` (fn_2_802EC: `fn_2_7630C(o, 1)`).
- **Out-params whose address sits in a saved reg and are read back via `lfs 0(rN)` (rep_2998 fn_3_E4CB0):** declare `Vec t;` and pass `&t.x,&t.y,&t.z`, read `t.y`/`t.z` directly; MWCC CSEs the member addresses into registers. Explicit `f32* py=&t.y` pointers or separate `f32` locals get folded to `lfs 0xc(r1)` instead. Also, a byte offset `off` used as `lbl.p44 + off` / `off += 4` may really be an index into an `s32*`: `((s32*)p44)[k] = x; k += 1;` gets strength-reduced to the same code with a different (matching) register priority.
- **Float compare functions** (`return -1` / `return a > b`): read both values into locals first (`f32 x = *a; f32 y = *b;`). The register order then matches.
- **Known blocker: float constant pooling.** Functions that use several `.rodata` floats get a single pooled base register in our build (`...@l` held in a saved register), while the original does `lis`/`lfs` per constant. No source form found yet; skip float-heavy functions with many constants for now. A single `extern f32 lbl_3_rodata_XXXX;` constant works fine. Declaring every constant as its own `extern const f32/f64` (real symbol names) avoids the pooling in some functions; a local `M12 id = lbl_3_rodata_XXXX;` copy works for identity matrices.
- **Float compare against 0:** `if (v)` emits `fcmpu f1,f0` (call result first) like the original; `v != 0.0f` swaps the operands. `x / 2.0` gives `fmul f0,f1,f0` where `x * 0.5` doesn't.
- **Unused-looking float arg in a callee:** if the original multiplies a constant into f1 and the constant sits in f2, the callee takes `(.., f32 a, f32 b)` and is passed the constant as 2nd float. Cast the call: `((void (*)(int, int, f32, f32))fn)(...)`.
- **Float literal vs. extern rodata:** comparing against a literal (`0.17f`) instead of the extern rodata symbol can fix `lfs` scheduling; loading an extern float into a local first fixes others.
- **Float constant compare via bool value:** a `cntlzw/srwi./beq` for `x == 2` is `if ((u32)__cntlzw(2 - x) >> 5)` (fn_3_120FF8).
- **Float literal instead of extern rodata (fixes prologue scheduling and constant reuse):** `CTRLSetScale(c, 0.2f, 0.2f, 0.2f); a[0xB4] = 0.2f;` matched where `extern f32 lbl_3_rodata_2B28` did not (fn_3_E45A8, fn_3_E45F0, fn_3_E2034, fn_3_13D5E8 with `100.0f`). Look up the value in the `.obj lbl_3_rodata_XXXX` block of `build/GYQE01/game/asm/...`. Works when a function uses one or two distinct constants; with 3+ the literals get pooled again, so use externs there. Declaring an unused `extern const f32` for a rodata symbol can break a *different* function that uses the same literal.
- **`2.5 >= PSVECMag(&v)`** (constant on the left) gives `fcmpo f0,f1; cror eq,gt,eq`; `PSVECMag(&v) <= 2.5` gives the swapped form.
- **Loop counter registers:** declaring `s32 off; u32 i;` and assigning `i = 0; off = 0;` after the float setup (not in the declaration) fixed which saved reg got which (`fn_3_B98E8`). Declaring a float local first gives it the higher f-reg (f31).
- **Compiler-unrolled copy loops:** `for (i = 0; i < 0x3C; i++) { copy 3 floats }` reproduces the 8x unrolled ctr loop with the `cmpwi r6,0x3c; bge` guard (`fn_3_F9F8`).
- **Float loop reg allocation:** a hoisted loop-invariant load (`lfs f1, 0xac(r6)` before the loop) needs its own local (`step = r->ac;` before `do`), and a `fmr` before the loop means the source copies a separate start value (`s = r->a4; if (s < lim) { v = s; ...`). `fn_3_82F80` is still ~70% after this; second block's float regs stay rotated.
- **Constants reloaded per use (no CSE across stores):** with `extern f32` constants the compiler sometimes keeps one in a register across stores to `g_Ball[]` (`fn_3_9B74` stuck), while `fn_3_BC54` reloaded as in the original. Untangled cause not found; float literals instead give the pooled-base blocker.
- **Float clamp:** `clip3FFF(f32)` that compares the float against 16383.f before converting; `x < lo ? lo : (x > hi ? hi : x)` for signed clamps (`bgt` then `mr` shape).
- **`fmuls` operand order** follows how the product is split: `sScale = a * b; x += (s32)(sScale * c)` fixed `mcmdSetADSR`; `(a*b)*c` in one expression did not.
- **Float constants as locals fix scheduling (fn_3_14D318):** `f32* d = (f32*)data; f32 h = 0.5f; ... d[3] * h` matched where the bare literal did not.
- **Float literal for the constant used once or twice, `extern f32` for the rest** (fn_3_A4158 `2.0f`, fn_3_BB07C `100000.0f`/`0.0f`); declare the float locals in the order `f32 s; f32 a; f32 c;` to get f31/f30 right.
- **Float callee-saved register order: brute-force the local declaration order (fn_3_1045A8).** Generate all permutations of `f32 a; f32 b; ...` with a script and score with `fnvariants`. When two values share one saved register in the original (`fmr f29` twice), try both one reused variable and two separate variables. Here it took two variables (`pitch`, `yaw`) plus the order `sinPitch, cosYaw, yaw, pitch, dist, sinYaw`.
- **`lwzu r8, g@l(r3)` (load a global pointer and keep `&g` in r3 for reloads) comes from writing every access through the global** (`*(f32*)(lbl_3_common_bss_DE94 + off) = ...`), with 3 constants as `extern const f32` so they aren't pooled (fn_3_104740).
- **Loops over `lbl_8036E548+0x2D94` entries with strength-reduced table pointers (rep_3310):** the saved-reg order (i in r31/r26 first) came only from the declaration order of plain locals assigned inside the loop: `u8* e; f32* v; u32 i;` (fn_3_1179EC) and `u8* e; s32 i; f32* v;` (fn_3_11887C). A permutation script over the decls found both in one run. A table read only for `i >= 4` with `-0xC0(rN)` displacements is `(f32*)(tbl + i * 0x30 - 0xC0)`, not `(i - 4) * 0x30`.
- **Float operand order (fn_3_F4C4C):** `f32 a = -x; a = K * a;` gave `fmuls f31, fK, fNeg` where `K * -x` and `-x * K` did not; `c = cos(a); y = K * -c;` fixed the second one.
- **One `fctiwz` but several `stfd`/`lwz` pairs (fn_3_111038):** each distinct conversion expression gets its own stack temp, sharing the fctiwz. `arr[i] = f; cur[i] += (s16)f; call(f)` gave the original's 0x20 / 0x28 / 0x28 slots; using `(s32)f` twice CSEs the second `lwz` away.
- **Repeat a common subexpression instead of a local (fn_3_14B3F4):** writing `(1.0f - t)` in each of three lerps (CW CSEs it) gave the original f3/f4/f5 allocation; a `u = 1.0f - t` local did not. Likewise `d = *(s16*)(a+0x34) - *(s16*)(a+0x36)` with the 0x34 field re-read later (no `s16 n` local) gave the original load order.
- **Loop with two float constant stores and a `li r0,N` ctr scheduled after the first `lfs`:** float literals (`10000.0f`, `0.0f`) instead of the `extern f32` rodata symbols fixed the scheduling (fn_3_39DC4).
- **Float args loaded before the pointer args' `addi r3/r4, r1, N` (no `mr r5, r3` copy of the incoming pointer):** the callee takes the floats *first* in its prototype (`fn_800528C0(f32, f32, f32, s16*, s16*)`); GPRs and FPRs are assigned independently, so the registers are the same but CW evaluates args in source order (fn_3_F9088).
- **Statement order picks `addi`+`stfs 0(rX)` or `stfs sym@l(rX)` for a global float (fn_3_8C2DC):** permute the stores in a block; `g176C = k / d; flag = 1; g1764 = hi;` gave the direct stores.
- **Float rodata externs: declare them all `const` (fn_3_106BA0):** a loop that stores five different float constants only hoists all five into callee-saved FPRs (`lfs f27..f31` before the loop) when every `extern` is `const f32`. With a mix of `const` and non-const (or all non-const) the compiler reloads one constant inside the loop (or hoists the addresses instead), changing the frame size and saved-register set. Check the `const`ness of the externs first when the diff shows a different number of saved `fN`/`rN` registers.
- **Shared tail with `li r3,1; blr` (fn_3_7F2D8):** a `goto fail;` label at the end (`fail: ...; return 1;`) reproduced multiple branches to one failure block; constant compares use extern `const f32` per rodata symbol.
- **Two different int-to-float magic doubles in one function (fn_3_14A37C, rep_3880):** the signed magic (`xoris` then store) and the unsigned magic (`stw r0` without `xoris`, rodata `4503599627370496`) are separate rodata symbols; the unsigned one comes from `(f32)(u32)(...)` or a `u32` counter. If a hoisted-constant loop has two `lfd` magics, one conversion is unsigned.
- **Hoisted constants into f27-f31 in a loop (fn_3_14A37C):** every constant extern must be `const f32`/`const f64` (including a zero used as `lbl[0]`); then the loop preheader hoists them. Order of hoisting follows first use, so compute `tf = (f32)conv; ang = K * tf;` as two statements to get the magic double before `K`.
- **Pooled-looking float consts in small funcs (fn_3_148EF0, fn_3_14C3BC):** one literal (`100000.0f` in fn_3_14C3BC, `0.0f` in fn_3_148EF0) with the rest as `extern const f32` matched where all-extern or all-literal did not. Try each constant as literal/extern separately (2^n variants through `fnvariants`).
- **Local declaration order picks saved registers (sta_c2 fn_3_CE954):** declaring `u8* st; f32* v; u8* g; s32 i;` (initialised later, in a different order) gave st=r30, v=r29, g=r28, i=r27; a base pointer `u8* b = lbl_3_bss_A018;` declared first gets r31. Take the order from the original's register numbers, not the order of the initialisers. Bool tested later: `f = (t[0x69] == 2); if (f != 0)` gives `subfic/cntlzw/srwi.`; the pointer/counter increments' source order (`i++; st++; v += 3;`) changes the bottom-of-loop schedule.
- **Float `0.0f` as a literal, not `extern f32 lbl_3_rodata_2664`,** moved the zero load into the original's position in fn_3_CE954/fn_3_D1110/fn_3_D196C (`0.5f`); for fn_3_D1280 the externs matched instead. Try both for every float constant.
- **fmadds vs fmuls+fadds (fn_1_151F8):** `v = x + step * K` fuses into `fmadds`; `step = step * K; v = x + step;` gives the original `fmuls; fadds`. Both an `extern const f32 sym` zero and a literal `0.0f` occur: call arguments of `0.0f, 0.0f, 0.0f` reload from one base register (`lfs f1, 0(r31)`), stores of the same value hoist to `f30` (fn_1_1620C).
- **Order of equal-constant stores (fn_1_1347C):** six stores of the same `lfs` value + one other: source order `B A C D E F` (the zero at +0x108 first, then the -0.8 at +0x10C) fixed the f-register numbering; the permutation search is cheap (`fnvariants` over the 6! orders).
- **Float loads into locals, constant read first (fn_3_754B8):** for `p[0x74] = 0.5f * (d[0] + d[1]); p[0x7C] = d[0]; ...`, load all four `d[i]` into locals and also take the constant into a local *before* them (`h = lbl_3_rodata_1250; a = d[0]; ...`). Locals alone fixed the f6..f9 assignment but scheduled the constant load late through `addi`+`lfs 0`.
- **Float compare operand order (`fcmpu f1,f2`):** `if (0.0f_extern == PSVECMag(v))` and `if (PSVECMag(v) == z)` both emit `fcmpu z,mag`. Store first: `m = PSVECMag(v); if (m == z)` flips it (`fn_3_169E70`).
- **Stale first arg in a tail call (fn_3_BC850):** if the original's temps skip r3 (`lis r5; addi r4` instead of r3) and the callee takes floats, the callee also receives `r3 = a`; cast the call `((void (*)(int, f32, f32))fn)(a, x, y)`.
- **Split float expressions into locals:** `hi = d[1]; lo = d[0]; step = hi - lo; step = step / 5.0f; x = step * (f32)idx + lo;` (one statement per step) matched the register numbering where the single expression did not (fn_3_20EEC).
- **Float `a*idx + lo` with a precomputed span:** `f32 lo = d[0]; f32 st = d[1] - lo; st = st / 5.0f; x = st * (f32)idx + lo;` (three statements) gave the original f2/f3 allocation; one-expression forms did not (fn_3_20EEC).
- **Lerp with `1.0 - k` (double) and `k` (float):** declare `f64 k1;` before `f32 k`, then assign `k1 = lbl_3_rodata_4048 - k;` to get the original f4/f3 assignment; use `extern const f32/f64` per rodata constant (`fn_3_16B5B4`).
- **Two float rodata constants pooled via one `addi` base (`lis r4; addi r5,r4; lfs 0(r5)`):** use float literals (`0.5f`, `0.0f`) instead of extern symbols; with the externs the registers swapped (`fn_3_C9C94`). A `s8` temp loaded from a byte needs `s8 prev` (an `s32` gives a different extsb placement) (`fn_3_C9B5C`).
- **Identical copy-pasted prologues** (`fn_3_F3AE0`/`F3BB0`) are separate bodies; load `z`/`x` into locals right after the stores to reproduce hoisted `lfs` order.
- **Cloned render/matrix helpers:** when a function looks like an already-matched sibling (`fn_3_B8184` vs `fn_3_C2310`), copy the matched body and only change the constants/globals. Use `Mtx` locals and a `(f32 (*)[4])` cast for `PSMTXConcat`; declare the callee prototypes only if they do not clash with `Dolphin/mtx.h`.
- **Struct copy of a rodata constant plus `memset`:** `Vec pos = lbl_3_rodata_2080;` copies with three `lwz/stw`, and `PSVECMag(&d) <= lim` (limit loaded into a local first) gives `fcmpo f1,f31; cror eq,lt,eq` (`fn_3_C5CE0`).
- **Float loads scheduled early:** reading `x`, `z` into locals (`z` first) before the stores moved the `lfs` above the stores in `fn_3_F3AE0`. A unused-size struct pad must be referenced (wrap it in a struct with the Control) or the compiler drops it and the frame size changes (`fn_3_F65C8`).
- **Repeated store blocks at a fixed stride (`fn_3_60768`):** four identical blocks that reload the base pointer each time are a `for (i = 0; i < 4; i++)` with `e = *(u8**)(base + 0x60) + i * 0x90` that the compiler unrolls. Plus literal `0.0f` instead of an extern for the one float constant.
- **Float literals for a pair of rodata constants (`fn_3_8B9BC`):** `0.0f` / `-1.0f` literals matched where `extern f32` symbols gave a different load schedule. Stack vectors: the first-declared local gets the higher stack address.
- **`if (PSVECMag(&v))`** (not `!= 0.0f`) gives `fcmpu f1,f0` in the original order (`fn_3_8B718`).
- **Unrolled constant-count loop reproduces repeated blocks that reload a pointer** (`fn_3_60768`): four identical stores at stride 0x90 with `lwz r3,0x60(r6)` before each is `for (i = 0; i < 4; i++) { u8* p = *(u8**)(sym + 0x60) + i * 0x90; ...p[0x38]...; }`. Use the literal `0.0f` rather than an extern rodata float so a single `lfs` is hoisted.
- **Index with the loop counter, not a walked pointer:** `((RunnerT*)g_Runners)[i]` with `int i` matched where pointer walking gave `stfsu` and an `s8` counter didn't unroll (`fn_3_8A4E4`, `fn_3_8604C`).
- **`crclr cr1eq` before a `bl` with no float args:** declare the callee variadic (`extern void f(void* p, s32 n, ...);`). A `()` declaration does not emit it (rep_3310).
- **u32→f32 of a zero that wasn't folded** (`lis 0x4330`/`lfd`/`fsubs`): store 0 to the u16 field, then read it back into the float field, before any later store (`fn_3_11AB2C`).
- **`extern const f32` lets a constant load move above a store through a pointer** (`lfs K` scheduled before `stb r0,0(r3)`). Plain `extern f32` keeps the load after the store because of possible aliasing (fn_3_E4658).
- **Compute a negation into the variable first:** `ang = -x; ang = K * ang;` gave `fneg` before the constant load (`fmuls f31,f0,f1`); `K * -x` and `-x * K` didn't (fn_3_E2F4C). Read a field again after a call into a fresh local to get the reload instead of a saved f-reg.
- **`addi rN, sym@l; lfd fX, 0(rN)` for a double constant (instead of `lfd sym@l(r3)`) comes from `extern const f64 sym;` used in two expressions** (`x += K; y += K;` loads it once through the `addi`). The u8->double magic constant gets the same form automatically (fn_3_CED40, fn_3_CEE5C). In the same file, `0.0f`/`100.0f` literals instead of `extern f32` fixed the constant-load scheduling in fn_3_D1848.
- **Two `fabs` then two `frsp` (`fabs f2,f4; fabs f3,f1; frsp f1,f2; frsp f2,f3`, fn_3_1354BC):** keep the results as doubles, then convert: `f64 ax = fabs(a - x); f64 ay = fabs(b - y); f32 fx = ax; f32 fy = ay;`. `f32 ax = fabs(...)` reuses f1 and swaps the registers. In the same function, `slwi r3,r3,6; addi r0,g@l; add r5,r0,r3` came from a per-field base, `((f32*)(G8 + 0xBB0))[idx * 16]` / `((f32*)(G8 + 0xBB8))[idx * 16]`; `G8 + (idx << 6) + 0xBB0` and struct indexing gave a different register or `add` order.
- **`addi rE, rP, 0x72c` emitted before a `lbz/lfs` at `0x754(rP)`/`0x744(rP)` (fn_3_113D20, fn_3_114204):** read the field through the already-formed element pointer (`a = e[6];`, `((u8*)e)[0x28] == 2` with `e = p + 0x72C`) rather than through `p + 0x744`; the compiler folds the offset back onto `p` but schedules the `addi` first. Also build `p = g_Minigame + i * 0x2C;` inside the loop instead of `p += 0x2C` to get the base straight into the saved register (no `addi r0; mr`), and declare variables first and assign afterwards (`u8* p; ... p = g_Minigame;`); declaration order then picked the saved-register assignment (permute it with fnvariants).
- **Unrolled GX quad loop (fn_3_16D810):** `for (i = 0; i < 4; i++) { GXPosition3f32(x + p[i*3], ...); GXColor1u32(*(u32*)&col); GXTexCoord2f32(u + t[i*2], t[i*2+1]); }` unrolls into the `lfsu`/base-offset shape; `GXColor col = <extern GXColor rodata>` gives the stack copy; `f32 t = K * (f32)n; f32 u = t * K2;` (separate temp) fixes the f1/f31 split. Each rodata float as its own `extern f32 lbl_3_rodata_XXXX` avoids pooling. A byte loaded into r5 before a call is often a stale register, not an argument: check the callee prototype in other units first (`fn_800A7D4C(int, void*)`).
- **`frsp f2,f1` + `stfs f1` (value used as double after being stored) (rep_1200 `fn_3_70838`):** store the result in the struct field and then re-read the field, e.g. `*(f32*)(p+0x108) = Rand(); *(f32*)(p+0x2C) = 0.5f * (*(f32*)(p+0x108) + *(f32*)(p+0x2C));`. A local `f32`/`f64` for the temp gives no `frsp` or a different one. Same for a negated value (`*(f32*)(p+0x20) = -(x / y)` then use the field).
- **`g_Fielders[fl*0x268 + 0xB4]` as `mulli r0; add r5,r5,r0` (rep_18E8):** `u8* fp = g_Fielders; fp += fl * 0x268; *(f32*)(fp + 0xB4)`; written inside a `||` as `fl < 0 || (fp = g_Fielders, fp += fl * 0x268, *(f32*)(fp + 0xB4) > 4.0f)` to stop the compiler hoisting the multiply above the `fl < 0` test.
- **rep_AC8 fielder-block patterns (b022):** (1) a single `5.0f`/`0.0f` literal in a function that otherwise uses `extern f32 lbl_...` constants matches where the extern gave shared-address `addi` loads or the wrong hoisting (fn_3_3C484, fn_3_3C270); with 3+ literals CW pools them behind a `...rodata.0` anchor, so mix: literals only where one const is needed. (2) `li r0,9; cmpwi r0,0; blt` after a fully unrolled counted loop is `if (i >= 0)` on the loop counter after the loop (fn_3_3740C). (3) `__abs(a - b)` (declare `int __abs(int);`) gives the `subf/srawi/xor/subf` abs with the sign in r0; `if (d<0) d=-d` gives a different register. (4) `lfsx fX, rBase, rOff` for a struct's first float needs `u8* base = g_Fielders; int off = idx*0x268; f = base + off;` with the read written `*(f32*)(base + off)` (fn_3_37610). (5) Re-reading `*(int*)(tbl+0x70)` twice (no temp) vs temp local: both appear, try each when r4/r5 swap.
- **Trip-count-3 unrolled-by-3 `ctr` loop, SOLVED (fn_3_A83C, rep_540):** it is a 9-iteration single-vector shift, not a 3-iteration loop: `for (i = 9; i > 0; i--) { *(f32*)(g + 0x1A8C + i*12) = *(f32*)(g + 0x1A80 + i*12); ...x3 floats }` (index straight from the global with `i*12`) gives `li r0,3; addi r3,base,0x6c; mtctr` with the 3x-unrolled body. Writing the 3-vector body in a `for (i = 3; ...)` loop is fully unrolled instead.
- **`extern const f32 lbl_3_rodata_XXXX;` fixes load scheduling (sta_c5 fn_3_F22FC, fn_3_F1750):** with plain `extern f32` the compiler won't hoist a rodata float load above stores to other floats (maybe-alias); with `const` it hoists like the original (`lfs` of the next constant lands before the `fmuls`/`stfs`). Try this first when only float load/store order or f0/f1 naming differs.
- **Two `fabs` results converted to f32 (fn_3_F2724):** `f64 ta = __fabs(a); f64 tb = __fabs(b); ax = ta; az = tb;` (f32 ax/az) gives `fabs; fabs; frsp; frsp` with the right registers, where `ax = (f32)__fabs(a)` gives a different register order.
- **`f64 ta = fabs(a); f64 tb = fabs(b); dx = ta; dz = tb;` also fixes two-fabs register order in rep_3520 (fn_3_137B10, fn_3_1379A0):** same trick as fn_3_F2724. Declare the f64 temps in the block, assign both fabs results first, then narrow to f32.
- **sta_c2 (fn_3_CC1D4, fn_3_D4CA4, fn_3_D4E00):** (1) When the same `extern f32 lbl_3_rodata_XXXX` (0.0, 0.75) is used several times in one function, we get a pooled `addi rN,..@l; lfs 0(rN)` where the original has `lis; lfs @l`: write the plain literal (`0.0f`, `0.75f`) instead.
