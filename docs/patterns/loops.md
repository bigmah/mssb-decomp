# Matching patterns: loops

Loop shapes, unrolling, induction variables, strength reduction, search loops. One pattern per line, so `grep -i <keyword> docs/patterns/*.md` returns whole entries.

- **menus 0788 small idioms:** `lbl_2_bss_1A824C[0] + 0x190000` as `u8* ctx` then `*(s16*)(ctx + 0x7706)` gives the shared `addis`. A byte read compared with `cmpwi` (not `cmplwi`) is `s32 flag = base[idx + K]; if (flag == 1)` (a `u8` local gives `cmplwi`). `lbz; extsb` into an argument register wants `*(s8*)(G[0] + K)` passed directly. `s32 sum = item->index; sum += *(s16*)(...)` (separate `+=`) keeps index and sum in one register; `s16 index = item->index;` (not `s32`) swaps the index/G registers into the original order (fn_2_30894). A row/sum with a trailing `+9` that the compiler folds into `lbz 9(rN)` instead of `addi 9; lbzx` (fn_2_2B884) and a 4-live-register pick (fn_2_2BF20, fn_2_25A48 scheduling, fn_2_262D0 lis order, fn_2_3039C constant hoisting, fn_2_28EA0 saved-register load, fn_2_2F544 loop base/walker swap, fn_2_26AF4 switch root 4) are still open.
- **Near misses (menus 71EC4, agent a5e):** fn_2_7E194 (36 lines: the unrolled `lbl_803C6724[j + 0xB]` search walks with `addi r3,r4,1; lbz 0xc(r4)` in the original, ours walks in place; base/v regs r4/r5 vs r3/r4), fn_2_72A88 (8 lines: only `lhz`/`lis DATA`/`lis lbl_80371C30` register order at the store block; best form uses `u8* t = lbl_80371C30; t += o14 * 8; *(s32*)(*(u8**)(t + 0x10) + 0x5C) = lbl_2_data_2AF08[found] << 18;`), fn_2_7302C (still ctr-converted), fn_2_7F8BC (4 lines: `s8 t = tbl[...]; if (t == v)` puts the table byte first; `s32 x = (s8)(tbl + idx9)[found + 2];` before the stores; only the `lbz` of x lands in r4 instead of r11), fn_2_808D8 (26 lines: fn_2_760CC body pasted into the `else` of `if (GS[7] != 5) ((void (*)(u8*, u8))fn_2_7630C)(o, index);`, with `u8* f = (u8*)&lbl_2_bss_F410` assigned at the top of the block, hoists the base like the original; decls `s32 b; s32 a; u8 x; u8 y; u8* e; u8* f;`; only the `lbl_803C6724`/`lbl_8034E9A0` base registers r7/r8 stay swapped), fn_2_7805C (150 lines: the original keeps the `lbzu` byte raw in r31 and re-`extsb`s it at each use; CW always CSEs our `(s8)v`).
- **Extra pointer move at loop setup (`fn_2_16CE0`, `fn_2_16D38`, `fn_2_48D54`, `fn_1_11C98`):** a manually advanced local pointer can emit `addi r0, base, ...; mr rN,r0` where the original initializes the induction register directly. Write the accesses as `base + i * stride + field` in a `for (i = 0; i < count; i++)` loop instead; MWCC strength reduction creates the matching pointer walk without the extra move. If only the loop counter and a loaded object swap registers, move the object declaration to function scope before the counter (`fn_2_16CE0`).
- **`while (n--)` empty delay loops:** `for (i = 13; i != 0; i--) {}` gives `li r0,13; mtctr r0; bdnz`.
- **Pointer-array loops:** `((u8**)sym)[i + OFF/4]` (indexed by the loop counter) or `u8* b = sym; ... b += 4` reproduces the original's `lwz OFF(rN)` / `addi rN,rN,4` shapes.
- **Reuse one local** for an index and a later loop counter, or write `q[0x34] = i = 0;`, to keep the original's register sharing.
- **Pointer induction loops:** `while (k-- != 0) p = *(u8**)(obj + 8 + k * 4);` gives the `subi r30, r30, 4` induction pointer.
- **Bottom-tested update order in `for` headers:** `for (...; i++, a += 0xC, b += 2, c += 1)` vs another order changes where the `addi`s are scheduled (fn_3_13F6C8). Try all 24 permutations with `fnvariants`.
- **Do-while with two pointers advancing at different strides** (`u8* m` +1 and `s16* sp` +1): declaring the pointer locals in a different order changes which one gets r4/r5; permute declaration order with a script.
- **Search loop with the "found" body after it (fn_3_108854):** the original's fully unrolled 4-iteration search plus one shared tail is `for (...) { if (cond) goto found; } return 0; found: ...`; putting the body inside the loop (or `break` + `if (i == 4)`) gives a ctr loop instead. Order of the tail's first three stores still decided the register picks.
- **Unrolled prefix + loop from 1:** four `stb` to `base+0x133+k*0x154` followed by a loop starting at element 1 is two source loops (`for (i=0;i<4;i++) a[i].x=0; for (i=1;i<4;i++) ...`). Index the global directly (`((T*)g)[i]`), not via a cached `T* rs = g`, or an extra saved reg appears (`fn_3_89028`).
- **Two identical loops over different variables** (`macHandle`): use separate locals (`sv`/`sv2`) to get the separate registers.
- **Nested fixed loops fully unrolled with `cmpwi r0,0xa` leftovers:** plain nested `for` over a typedef'd struct with `s16 a[4]; u8 b[4][10]` matched (`fn_3_142CA8`).
- **Fixed 4/9-element loops over a struct array get fully unrolled by the compiler** when written as `for (i = 0; i < N; i++) { ...; r += 0x154; }` with a `u8* r` pointer (fn_3_27648, fn_3_86DFC); `for (i = 0; i < 4; i++) { RunnerT* r = &((RunnerT*)g_Runners)[i]; }` with `typedef struct { u8 b[0x154]; } RunnerT;` fixes the pointer-induction form (fn_3_88F98).
- **Loops with several induction pointers (`addi r28,g@l; li r27,0; ... li r29,0`, no `mr`):** index with the counter only (`g_Minigame + i * 0x28 + 0xA8`, `base + i * 0x28`) and let CW strength-reduce. Hand-written `m += 0x28; off += 0x28` pointers gave an extra `addi r0; mr r28,r0` (`fn_3_11874C`).
- **Declaration-order hill-climb:** for a big loop where only register numbers differ, shuffle the local declaration order randomly (100+ files, score with `fnvariants`), then swap/insert-move declarations greedily on the best (`fn_3_94BC4` 117 -> 6 diff lines). Two nested loops over 5-byte struct rows: take `s8* pa = p + 0x12` style pointers before the inner loop to reproduce the original's hoisted `addi rN, r7, 0x13`.
- **Two copies of the same struct init with different base registers = an unrolled 2-iteration loop, SOLVED (fn_3_FD5A8):** `V3U v = rodata; for (i = 0; i < 2; i++) { u8* c = g_Camera + i * 0x9BC; ... }`. CW unrolls it: iteration 0 keeps `p = c+0x13C` in its own register, iteration 1 folds into `c+0x9BC` offsets. Hoist the rodata copy out of the loop to get a single dead stack copy (inside the loop gives two).
- **`g_Runners` as a typed struct array:** `extern RunnerT g_Runners[];` (local typedef padded to 0x154) and `g_Runners[idx].field` gives the original `addi base; mulli; add` order, where `(u8*)&g_Runners + idx*0x154` gave `addi r0`/swapped regs (fn_3_A1D04, fn_3_A32B8). For a backwards loop use `RunnerT* r = &g_Runners[3]; for (i = 3; i >= 0; r--, i--)`.
- **`beq` straight to the epilogue** on the first test means `if (x == 0) return;`, not `x != 0 && ...` (fn_3_8C104). `fndiff` printed MATCH while the report said 99.96%.
- **Zero-fill of an `s32` array member, 16x unrolled with `addi rX, rOff, 0x128+4k; stwx` (fn_3_1069C0):** index a typed struct member, `((S*)g)->arr[i] = 0;`. `*(s32*)(g + 0x128 + i*4)` or `((s32*)(g+0x128))[i]` give 8x unrolls with `slwi`/`add`.
- **Range merge of `x==1||x==2||x==3` on a loaded byte (fn_3_7EA68):** a local copy (`u8 st`) merges into `subi/cmplwi 1/ble`; testing `g_Pitcher[0x13E] == 1 || g_Pitcher[0x13E] == 2 || ...` directly gives the separate compares. Loop `for (k=1;k<4;k++) g_Runners[k*0x154+...]` gives the unrolled runner checks.
- **Store order picks registers in counted loops:** try `a += 1;` before `b.state = 3;` (fn_3_5C5C8, fn_3_5A6FC).
- **Zero-fill loops:** a `u16 [N][0x100]` extern with `a[ch][i] = 0` gives the 8x unrolled ctr loop (fn_2_50E5C); `s32 i = 0;` plus `for (; i < N; i++)` gives the `bgelr` guard.
- **Extra inductions as `mr rX, rZero`:** if the original has `li r9,0; mr r7,r9; mr r8,r9`, write one `for (i...)` loop using `i*stride` expressions directly; hand-written `off += ...` locals don't give it (menus fn_2_8DC00). Keep array loops indexed by the counter, not a walking pointer (fn_2_8DB14).
- **Struct-array bss loop with the `cmpwi 8; subi; ble` unroll shape:** typedef an element struct with padding and index `arr[i]` (fn_2_17AB8). A bound read as `lhz` is `*(u16*)`. `(s32)bytearr[x] == 1` gives `cmpwi`, plain gives `cmplwi`. Declare params `s32` when the callee doesn't `extsh`/`extsb`.
- **Loop kept for a 1-trip count (fn_1_1620C):** `for (i = 0; i < 1; i++)` gets peeled; `i = 0; do { ... i++; } while (i < 1);` keeps the `cmpwi r27,1; blt`.
- **Unrolled init loop with a field offset (fn_1_14710):** `((u16*)object)[i + 0x39] = i;` keeps `sth rX, 0x72(r8)` (offset in the store, pointer starts at `object`); `*(u16*)(object + 0x72) + i` pre-adds 0x72 to the pointer instead. Shared branch targets from `if/else` ladders: write the original's `beq YES; b NO` layout with `goto yes; goto no;` labels (mode `< 0x2C ? == 0x10 : < 0x30`). Pair-table walks: `p++` pointer plus a separate byte index `k += 4` used as `*(u16*)((u8*)tbl + k)` against the symbol, not a copy of `p`.
- **Locals declared in an order that decides r27..r31:** when pointer/index locals come out permuted, add `u8* q;` as a separate declaration assigned later (not `u8* q = ...` inside the loop) (`fn_3_169D00`).
- **CW unrolls constant-trip search loops:** `for (i = 0; i < 7; i++) { if (i == m || i == m+1 || i == m+2) continue; if (r == 0) break; r--; }` gave the 7-way unrolled chain (fn_3_20FB0); only register numbers needed fixing by declaration order.
- **`if/else if` chain instead of `switch` for small case sets:** CW emits a jump tree for `switch (u8)` with cases 1..3, while the original compares the same reloaded byte with `cmplwi` per case (fn_3_21768, fn_3_20FB0).
- **Index a pointer array with the loop counter instead of a manual byte offset:** `((u8**)*(u8**)(t + 0x18))[i]` lets the compiler build the strength-reduced `addi rN,rN,4` induction register (the `off += 4` version gives the right code with two registers swapped) (`fn_3_C3F70`).
- **A local `u32 i` loop counter passed to a `u8` parameter** gives `clrlwi r4,r30,24` at the call and a bare `cmplwi` in the loop test (`fn_3_C298C`); a `u8 i` gives the opposite.
- **Brute-force near-matches that differ only in saved-register numbers:** generate variants with a script and score them all in one `fnvariants` call (about 0.15 s each, so 5000 variants is about 13 min). Axes that have paid off: permutations of the local declaration order (`fn_3_13E6D4`: `s16 t;` before `u32 i;`; `fn_3_3638`), the declared type and source expression of a local (`vsSampleStartNotify`: `u8 v = voice & 0xFF;` instead of `u32 v = (u8)voice;`), and `a++, b += n` update order in a loop (`fn_3_3638`: `e += 0x1C, i++`). Split `T x = init;` into `T x;` plus assignments, then permute the assignments too (`fn_3_62CA8`).
- **`add r3, rBase, rOff; lwz r12, OFF(r3); mtctr; bctrl` in a loop means the element is passed as the argument:** `objs[i].fn(&objs[i])`. Without the argument every form gave `addi r0, rOff, OFF; lwzx` (`fn_3_B93CC`).
- **Index the output array, walk the object array with a pointer:** in `fn_3_B867C` the `out[n++]`/`out[--k]` writes became strength-reduced pointers next to the kept counters, which matched. Writing those pointers by hand changed the register allocation, and indexing the global object array reloaded its base every iteration. `do { ... obj--; } while (i-- != 0);` gives `cmpwi i,0; subi; bne`. `obj = &objs[count - 1]; i = count - 1;` gives the `mr r6, r4` copy.
- **Global struct accessed directly (no local pointer):** `#define G (*(T*)lbl_3_common_bss_35154)` and `G.field = ...` throughout reproduced the original's two separately materialised bases (`addi r6` for the first block, a fresh `addi r5` after the loop) where `u8* c` locals gave swapped registers (`fn_3_BD434`).
- **Loop writing `p->arr[i].x` with `p` stored first:** `*(T**)(q + 0x24) = p = (T*)sym; for (i...) p->pts[i].x = ...` (T has `u8 pad[0x4C]; V2f pts[]`) gave the original `addi r30, sym@l` with no `addi r0; mr` copy (`fn_3_BDE14`).
- **`subi r3; mulli r0,r3; mr r8,r3` (counter copied from the element-index temp, `fn_3_E7388`):** write the pointer first from its own expression, then the counter: `e = &g->arr[g->count - 1]; i = g->count - 1; do { ...; e--; } while (i-- != 0);`. CSE turns the second `count - 1` into the `mr`. `i = n - 1; e = &arr[i];` merges them instead.
- **`addi r8, r3, 0x30` then `stb 1(r8)`/`stb 2(r8)` after `stb 0x30(r3)` (`fn_3_E7424`):** this is the TU's own `.bss` statics (a `u8[4]` static at base+0x30) addressed from a shared section base. `u8*`, struct and loop forms on one extern all fold to `0x31(r3)`. Matching it needs the unit's `.bss` (AE50..AEE0 in sta_c6) defined as `static`s (see the pooled `.bss` base entry above).
- **Order of zero-initialised loop counters (fn_3_1360BC):** `for (i = 0, k = 0; ...)` emits `li` for `i` first; `k = 0; for (i = 0; ...)` emits it for `k` first. In the same function, moving the `n = K;` initializer to after the other prelude statements (plain declarations, then assignments in the original's load order) fixed a saved-register swap between `n` and `pts` that no declaration order fixed.
- **Loop with `i` and a separate `off += 4` register (`fn_3_E5A84`):** that is CW strength-reducing `((u8**)arr)[i]` in a `for (i...)` loop; don't write the two counters by hand, index with `i` and let it generate them. Local `Control c` declared before `Mtx m` puts `m` at the lower stack offset.
- **rep_3DA8 scout-flag loops (fn_3_1637EC, 163948, 163A7C, 163BD4, 163D34, 16440C):** (1) the unrolled-by-3 `ctr` loop has a dead `addi rN,rN,2` counter; give the second loop its OWN variable (`for (j = 0; ...)` with `i` only in the gather loop) and place `s32 j;` in the right declaration slot (try all positions) to get the counter and the loaded flag in the right regs. (2) A pointer that advances in the body is `q[j*K + off]` indexing, not `p += K` (`p[0x13]` -> `q[j * 5 + 0x13]`); the `p = q` copy then appears as `mr` like the original. (3) A byte flag compared twice with `extsb.`/`extsb` is an `s32 m = *(u8*)...; if ((s8)m != 0 && (s8)x < (s8)m)`; fold `b*6+a` into the load expression so it hoists. (4) Globals the original keeps in registers (tracker, `lbl_3_common_bss_37400`, `g_Pitcher`, `g_Batter`) are locals with initializers (`InMemPitcherType* pi = &g_Pitcher;`), declared in a specific order (permute with `fnvariants`). (5) `lis/addi lbl_X+0x10` relocs mean the original references a separate symbol at +0x10: split the symbol in `symbols.txt` (`lbl_80109420`) instead of fighting constant folding. (6) Uninitialised `id` in r0 / unused arg in r3: declare it `s32` (not `s16`, which adds `extsh`).
- **Loop-invariant hoisting of global byte loads (fn_3_889FC, fn_3_88B18):** with `u8 g_X[]` externs, `r = g_Runners; r[0x123]` + `r += 0x154` in the loop does NOT hoist `g_Ball[..]` reads, but indexing `g_Runners[i * 0x154 + off]` directly does (stores are known not to alias other globals). Declaration order of plain locals (`int i; s16 t; int m; u8* r;`) swapped r7/r8 in fn_3_88B18; use a permutation script with `fnvariants`.
- **Hoisted pointer locals vs. in-loop computation (rep_3310 `fn_3_1192B8`, `fn_3_1189C8`, `fn_3_118164`):** when the prologue shows `mr`s the original lacks, or the saved-reg numbering is rotated, stop hoisting `u8* g = g_Minigame; ... g += 0x38` and compute `g = g_Minigame + i * 0x38;` inside the loop body (declare `u8* e;` at function scope, not inside the loop). In a non-loop function the order of local *first use* decides scheduling: assigning `u8* m = g_Minigame + i*0x38` before the `o = ...` pointer fixed `fn_3_1189C8`. Declaring a separate `s32 j = i + 0x82;` (reused for the call arg and the pool index) fixed `fn_3_118164`. Declaration order of *uninitialised* locals has no effect; initialised/assigned order does.
- **Loop-header update order matters for scheduling of the increments** (`for (...; i++, a += 0x18, b += 2)`): permute all orders with fnvariants (fn_3_135A64, fn_3_137B10). Declaring the induction counter before the result flag (`s32 i; u8 ret;`) then assigning `ret = 0; i = 0;` in that order fixed saved-reg numbers and `li` order.
- **Open: a global base `u8* g = G8;` that is also used as a loop-pointer init keeps getting `addi r0,..; mr rN,r0` (a temp) where the original has `addi rN,r3,lo` directly** (fn_3_1356F8, fn_3_135A64, fn_3_135C18, fn_3_134658). Tried: block-scope decl, comma-init in `for`, chained assigns, typed struct pointer, all-`G8` uses, declaration permutations. None coalesce the temp.
- **rep_3310 (n005: fn_3_11A210, fn_3_11A92C):** (1) With several strength-reduced induction pointers in one loop, the saved-reg order follows the order each pointer is first *used* in the body (first use = highest reg): moving `g = g_Minigame + i * 0xC;` from the top of the loop to just inside the `if (g_Minigame[0x193A + i] != 0)` fixed r28-r30 (fn_3_11A210). (2) When only the `lis` order of rodata/bss addresses differs in one branch, permute that branch's 3-4 statements (brute force with fnvariants): putting `lbl_3_bss_B6BC = lbl_3_rodata_33CC;` before the `v[] = ...` stores matched fn_3_11A92C. (3) Use an `if/else if` chain on a loaded `u8` local, not `switch`, for a 2-case `cmplwi 1 / cmplwi 3` dispatch (switch gives `cmpwi/beq/bge` ladders). (4) `*(void**)(base + (i + 0x10) * 0x90 + 0x34)` (product + const, base added first) keeps the `mulli; addi r0,r3,0x34; lwzx base,r0` form even with a single use; writing the sum as `base + ((i + 0x10) * 0x90 + 0x34)` folds to `lwz 0x34(rN)` unless the value is CSE'd.
- **Small-state-machine pass (fn_3_14443C, 99%):** an `if (st == 0) ... else if (st == 1) ...` chain reproduces the original `cmplwi 0; bne; cmplwi 1; bne` ladder (a `switch` on the same u8 gave a `cmpwi beq/bge` tree). For an s16 field, `if (p->f != 0) p->f -= 1;` gives `lha; cmpwi; beq` where `p->f = p->f - 1` gave `extsh.`; `p->f -= 1` before a lerp also fixed the scheduling of the following `lis`. A fixed-count loop that always runs once is a `do { ... } while ((s8)j < 3)`, which drops the initial `b` to the bottom test. A local `Vec dir = {0.0f, 0.0f, -1.0f};` reproduces the lwz triple copy from the rodata symbol (fn_3_143770), unlike a struct copy from `extern const Vec`.
- **Indexed constant-table scan (`fn_2_689CC`, menus rep_0B08):** `memcpy(&candidate, &locations[current], sizeof(candidate))` in a normal `for` loop strength-reduces to the original saved table pointer. Maintaining `location++` explicitly instead emits an extra `addi r0,base; mr r31,r0` at initialization. Keep the best index as `s32` and return `s16` so narrowing happens only at the return.
- **Constant-trip `for` loops are unrolled by CW; write the original element count** (menus fn_2_442E8 9 entries -> ctr 3, fn_2_467FC 54 -> ctr 18). `u32 n = byte - 1; for (i = 0; i < n; i++)` gives `subi; mtctr; cmplwi; ble`; signed gives `subic.` (fn_3_107988). A do-while with `u32 i` and a `u8* p` that both advance (`p[off] = i + 1; i++; p++; } while (i < 6)`) gives the single pointer-induction loop (fn_3_1078F8).
- **Loop-invariant addresses: do not cache in locals (fn_2_6CCB8):** an unrolled `for (i = 0; i < 4; i++)` over `g[0]`/table lookups matched only when written with the full global expressions inside the loop; local `g`/`t` copies got hoisted before the call. `*(s16*)((u8*)t + idx * 8 + i * 2)` gives `add; lha 2*i(r3)`.
- **`switch` lowering hints (fn_2_851A8):** `cmpwi 0; bge A; b END` in the left subtree and `cmpwi 5; bge END` in the right means `case 0: case 1: case 2:` carry the body and there is NO `default`; an empty-range `case 0..3: break;` before `case 4:` reproduces a `beq; bge; b` pair. `fndiff` can say MATCH while branch targets differ; check `report.json`.
