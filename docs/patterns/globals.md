# Matching patterns: globals

Globals, arrays, struct fields, pointer arithmetic, sda/lis addressing, typed externs. One pattern per line, so `grep -i <keyword> docs/patterns/*.md` returns whole entries.

- **Symbol names must agree.** A header `extern` name and `symbols.txt` have to use the same name. Otherwise the diff shows a relocation mismatch even when the code is right. Rename in `symbols.txt` when the header name is better.
- **Pointer to a `s32` slot incremented in place (`lwzu`, fn_3_9E7D4):** index the array in each use, `((s32*)(g + 0xDC))[i]`, instead of caching `s32* p`.
- **`addi rX, base, K; add rX, rX, idx` (const first, index second):** the compiler folds `base[K + idx*n]` into `add; lbz K(..)`. Assign the const-offset pointer to a variable and add the index afterwards (`e = (T*)(d + 0x798); e += idx;`).
- **A `.sdata2`/`.rodata` symbol used by a function needs a split** (`.sdata2 start:... end:...` in `splits.txt`) before the report counts it as matched (see `Musyx/snd_math.c`).
- **Hoisted struct-element address before stores (fn_3_F65C8):** when the original computes `base + idx*0xE8` (lwz base, mulli, add) before some stores but loads the field after them, take the element pointer in a local at the top (`StadObj78* so = &((StadObj78**)sym)[0][idx];` ... `o = so->w78;`).
- **Rodata symbol names are not checked by report.json:** a function using `lbl_2_rodata_1080` instead of the original `1078` still scores 100%. After each match compare the `@l`/`@ha` relocs against the original asm.
- **`(tbl + a * 4)[b]` instead of `tbl[a * 4 + b]`** gives `lbzx` with the scaled base as the first operand (fn_3_21768).
- **`addi rB, sym@l` once, then `addi r3, rB, 0x30; addi r3, r3, 0x20` (fn_800097A0):** the original addresses several data objects of its own unit through one pooled base register. Not reproducible while that unit's `.data` is unsplit; commit as equivalent.
- **Unit without an `.sdata2` split (main/file_8000BA3C):** float literals and int-to-float conversions come out as `DATA@sda21` vs the original `lbl_803CC4xx@sda21`, so the function can't reach MATCH even when every instruction is right (`extern f32 lbl_...` changes the scheduling instead). Get it to "only the DATA names differ", commit as NONMATCHING with that note, and ask for the split.
- **Direct `lwz rX, g@l(rY)` vs `addi; lwz 0` for a pointer global (rep_0788 fn_2_200E4):** re-read the global in every expression (`(g + *(s16*)(g + 0x16C0) * 10)[0x40F6]`, `g[0x442B]`) instead of caching it in a `u8*` local; the local copy is what produces `addi; lwz 0`.
- **fndiff hides wrong `lbl_N_bss_*`/`lbl_N_data_*` names (fn_2_1DC8):** both sides are rewritten to `DATA`, so a MATCH can read the wrong bss block (it read `lbl_2_bss_F468` instead of `F410`). Take bss/data names from the m2c draft or `grep` the raw asm (`build/GYQE01/<mod>/asm/*.s`), not from the diff.
- **Linking a unit whose report says 100% fails the sha1 (Musyx hw_aramdma, hw_dolphin):** objdiff counted `bl salMalloc` as equal to the original `bl salMallocPhysical`. Find the first differing address of `build/GYQE01/main.dol` vs `orig/` and look at that instruction; wrong call targets and literal order (`.sdata2`) only show up there.
- **`.sbss`/`.sdata` order when linking (Musyx stream, snd3d, s_data, hw_dolphin):** uninitialised small data is laid out in reverse definition order, `= 0`-initialised ones in definition order before them; drop the `= 0`s and define in reverse address order. A static that must sit between them can be a global defined later (snd3d `s3dCallback`). Float literals land in `.sdata2` in first-use order (synth_adsr needed an inline `powf` wrapper so `2.0` came before `1000.f`).
- **main.dol game units need `-Cpp_exceptions on`** (set for the whole `unk` lib in configure.py): without it extab/extabindex come out empty and a linked unit shifts every later address.
- **File-static .bss layout in GC/2.6 (main/file_800263FC):** CW lays out a unit's static (and global) .bss objects by order of first reference in the code, not declaration order (reversing the declarations changes nothing; one function referencing a,b,c,d gave d,c,a,b). Functions touching several of them are addressed off one base (`lbl_8017EC00` + offset). Defining them as statics in the unit is only right once the .bss is split in and the reference order reproduces the original layout.
- **Linking a REL unit fails although every function matches (menus rep_01A0):** `-inline deferred` emits functions in *reverse* source order, so write them in reverse address order (and `.bss` statics/globals are also emitted in reverse definition order; initialised `.data` keeps definition order, jump tables go after it).
- **REL unit `.data`/`.bss` split boundaries (menus):** mwcc sections are 8-aligned, so a TU's `.data`/`.bss` starts on an 8-byte boundary (a 4-byte `gap_04_*` symbol marks a TU end). A split may end before alignment padding only if the next split is explicit; an auto split must start 8-aligned. A zero-initialised scalar goes to `.bss` (write `T x[1] = {0}` to keep it in `.data`). objdiff credits a data section only at 100%, so leave jump tables of `NONMATCHING` functions out of the range.
- **Weak `_half$localstatic3$dolsqrtf2` / `_three$...` in `.rodata` of every TU that includes math.h:** name the module's first copy (`.rodata:0` in menus/game) as those weak symbols in symbols.txt; the linker then drops the per-unit copies.
- **Pooled `.data` base (`addi rB, DATA@l` then `addi rX, rB, off` / `lbz off(rB)`) solved by defining the unit's tables in its .c (rep_EA0, kinoko, m_sound, rep_3310, auto_00_000DEB90):** dump the objects from `build/GYQE01/game/asm/auto_04_*_data.s` and define them (globals or statics, in address order, real types and initializers; split dtk-merged objects where the code addresses a sub-part separately, e.g. m_sound `lbl_3_data_8270/8278/8284` inside `81FC`). Code must name the objects directly (`tbl[i]`), not through a `u8* d = base + off` view. Did not work in a variadic function (rep_3CE0 fn_3_15FB84: no `...data.0` anchor was created).
- **`addi r31, DATA@l` held across a call, fields at +0x70/+0xA0/+0xA4 (fn_1_1538):** the "struct" dtk shows as one object is several TU statics (`files[7]`, `nodes[2]`, `mode`, `color`); define them as separate initialized `static`s in order and the function gets the pooled base. One static struct gave a plain `lis/addi sym` per use. Index the array directly (`ch_nodes[i].tex = ...`), a `node` pointer local swapped registers.
- **Pooled .data offset not folded (`addi base,0x218; addi 0x1e0` vs `addi base,0x3f8`, fn_1_9AB0):** CW only folds offsets at object starts; split the static array where the original folds (`ch_CC8[0x1E0]`, `ch_EA8[0x64]`, `ch_F0C[...]`). An inlined helper that reads a pooled struct must take that struct as a parameter (`showScore(b, v)`), or it rematerializes the base.
- **Pooled `.data` base (`addi rB, lbl_N_data_X@l` then `rB + off` for several objects; game rep_3310 fn_3_116840, rep_1E08):** MWCC pools a TU's own initialised data (globals too, not only statics) once their definitions come *before* the function. Define the unit's `.data` in C at the top of the file in address order (`tools/adddata.py`, then move the block up); functions that address the objects singly keep their `lis/addi sym`. fndiff then shows `...data.0` vs `DATA`, which report.json counts as matched.
- **main.dol unit .data has its jump table first instead of last (file_8001FE00):** main.dol game code builds with `-inline auto`, so a switch's jump table is emitted when its function is compiled; .data objects defined after that function land behind it. Define the data before the code.
- **Pooled `.bss` base appears only in some functions (rep_0138 fn_1_5544 vs fn_1_7EF8):** mwcc pools a TU's statics behind `...bss.0` only in functions that touch **three or more** distinct static objects (tested: two objects, even structs with many field uses, get per-object `lis/addi`). dtk sizes a symbol up to the next relocation target, so a "0x21C struct" may be several statics only reached through the pool (C4 s32, D1 u8, D4/D8 enums, DC u8 in rep_0138); define each at its own offset with filler statics in reverse order.
